/State.Selection/ *Show which item or option is selected through a clear visual treatment and text where needed.*
/State.Loading/ *Show a loading state only when waiting is part of the proposed flow. Do not imply measurable progress that the system cannot report.*
/State.Empty/ *Explain what is missing when there is no data and show the next useful action if one exists.*
/State.NoResults/ *Distinguish no search matches from a truly empty data set.*
/State.Error/ *Use a clear message that identifies the failure and a recovery action when one is available.*
/State.Success/ *Confirm a successful action only after it has actually succeeded; in a design prototype, label the state as illustrative.*
/State.Status/ *Never rely on color alone to communicate status.*
